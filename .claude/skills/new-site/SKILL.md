# New showcase site

The user gives a brief like: *"Day [N] — [Brand], a sneaker brand. Black and neon green, energetic. Hero video in raw/hero.mp4."*

**First, and again at the start of every round: read `docs/LESSONS.md`.** Then follow `CLAUDE.md` → "Building a new site — Round 0 + 5 rounds". Never skip a round, and stop after each round for the user's "ok". Explain things in plain simple language.

**The repo shows only the current project** (see `CLAUDE.md`): old sites live in their own day folders; git holds only today's site, the engine, the pattern library and the kit docs.

- **Skills to use:** `flow-prompts` (asset specs + checking + recording the prompts as run; it never writes prompts), `video-frames` (every scroll video), `record-check` (end of every round), `cover-check` (reel cover), `caption` (post text), `archive-day` (finish + commit), and the official `gsap-*` skills while coding motion. Effects M38+ and transitions X6+ are ready in `components/fx/` (see `/lab`); a travelling product object (F1–F8) in `components/fx/travel/` (see `/lab/travel/f1`, `/f3`, `/f6`): default to F1 (PNG) or F3 on OGL (the only 3D inside the budget).
- **Desktop only (permanent rule):** build and design for **1440×900** only. No phone UI (no mobile layouts, no small-screen breakpoints/media queries, no phone-only components or code paths) and no phone checks (no 360/390 screenshots, no phone steps anywhere). Round 0 Motion maps have no Phone column.
- **Round 0 layouts:** for EVERY section pick a **SECTION-MENU layout code** (`docs/SECTION-MENU.md`, live at `/lab/sections`) **and** a MOTION-MENU code. No layout code twice on a site and none used by the last 3 sites (SITES-LOG → Layouts column, and the Layout row in that day's uniqueness table).
- **Round 0 starts with the reference board, per section** (`docs/REFERENCE-SOURCES.md`, CLAUDE.md Round 0 step 1):
  1. `npm run refs -- <day> "<category>" --sections`, then **STOP for the user's OK** on the section list, then `--approve`.
  2. `npm run refs:search -- <day>` opens the search sheet (links to Pinterest/Dribbble/Behance only). The user saves shots and clips into `refs/inbox/` by hand; **wait for "inbox done"**.
  3. `npm run refs -- <day> "<category>"`: the inbox ("mine") goes first, then each section is filled to 3 options from allowed live sites (1 same business + 2 any business) + 1 clip.
  4. Look at everything, write each option's "what to take from it" line + tag, `--board`, then **STOP until the user picks 1 per section** (`--pick`).
  5. `DESIGN.md` from the picks: name each section's reference, mix ideas, never copy a layout, no real-brand look-alikes, **Hover map** + **Product detail plan** (templates at the end of `docs/MOTION-MENU.md`) + a **reel time table**, then the asset list (specs + code fallbacks, no prompts).
  - Never open Pinterest, Dribbble or Behance with a script.
  - **Usual case, the inbox covers only some sections:** after "inbox done", build **2–3 full-page layout mockups** (`day<N>/refs/layouts/*.html`, 1440 wide, code-drawn placeholders, every section labelled with its reference or "ours"). Any reference may inspire any section, and the uncovered sections are our own design. Render them, fix them, then **STOP until the user picks one**; it becomes the DESIGN.md direction.
- **Round 0 — Design direction:** first delete the previous site's images and frames (`public/images/<old-slug>/`, `public/frames/<old-slug>-*`) and any demo assets, so only the new site's assets exist. Read `docs/SITES-LOG.md` + `docs/DESIGN-MENU.md` + `docs/MOTION-MENU.md`, pick one option per menu (≥ 6 of 8 different from each of the last 3 sites), plan 9–12 sections (hero + cinematic + shop-style), write `site/DESIGN.md`, list missing assets with prompts. The "different from the last sites" table goes in `docs/SITES-LOG.md` only (never in `DESIGN.md`, so old names never enter the repo). Wait for approval.
  - **`DESIGN.md` must include a "Motion map" table** (template at the end of `docs/MOTION-MENU.md`): every section, loader, nav and footer included → **one motion code** (M1–M37), how it plays here, record mode (no Phone column: desktop only). **No code used twice. "Just fade in" is not allowed** as any section's motion. The hero and signature must not repeat **any** earlier site's hero or signature (check every row of `docs/SITES-LOG.md`, not just yesterday), and the hero must not be a "shape grows to full screen / portal" opening. Add the planned transitions (X codes) and details under the table.
- **Round 0 — Traveling object (every 3rd site):** Every 3rd site, starting Day 9 (days 9, 12, 15, 18, 21, 24, 27, 30), must have a TRAVELING OBJECT: one cut-out object that travels down the page with the scroll and lands in each section (Flip / MotionPath, from the floating objects menu F1–F8). Round 0 must plan its path section by section, say where it hides, and list the cut-out .png it needs (made from an existing asset with npm run cutout, no extra Flow images if possible). Calm easing, never covers text, never pauses in record mode. Check the day number first; plan it in `DESIGN.md` (its own Motion map row) and fill the SITES-LOG **Traveling object** column ("—" on other days).
- **Round 1 — Structure:** archive the old site, frames + images into per-site folders, install fonts, write `site/` from scratch (copy patterns into `site/components/` and restyle them), build the markup the Motion map needs, `npm run check` + `npm run build`. User reviews `http://localhost:3009/?static=1` on the laptop.
- **Round 2 — Big motion:** loader, hero, signature moment and every pinned / scroll-scrubbed section; everything interactive also plays by itself on screen. **Motion map check.** Run the checks and send the user the 1440 reel.
- **Round 3 — Section motion + transitions:** every other section gets its Motion map code, plus the transitions between sections. **Motion map check.** Run the checks and send the user the 1440 reel.
- **Round 4 — Details:** hover, cursor, micro-interactions as in the Hover map. Mark ≥ 3 of them `data-hover-demo` (`="click"` for swatches / Add to cart): the engine's record cursor glides to them in `?record=1` and plays their REAL hover (docs/RECORDING.md "Hover cursor"); `npm run check` and `npm run reel` fail under 3. **Motion map check** (1440 reel). Send the 1440 reel.
- **Round 5 — Polish, performance, archive:** readability, performance, `?static=1` final states, console clean, set `meta.record.duration` (25–40 s), add a row to `docs/SITES-LOG.md` (with the Motion column), add the day's new lessons to the end of `docs/LESSONS.md`, `npm run archive -- <day-NN-slug>` (skill `archive-day`). Final checks: `npm run reel` (PASS), `npm run check`; send the 1440 reel. Then run `git ls-files` and confirm the repo holds only the current site's assets, the engine, the pattern library and the kit docs (no other brand names or images); report the list and total size. Reply with the filming steps from `docs/RECORDING.md`.
- **Checks every round** (production server: `npm run build && npm start`): **`npm run reel -- <slug>-r<N>`** records `?record=1` at **1440×900 only** and runs freezedetect + frame-diff; it must PASS (low fps = busy machine → re-run). Fix every problem before saying the round is done; the user gets the 1440×900 reel.
- **Motion map check (end of Rounds 2, 3, 4):** go through the Motion map section by section; the main move must be the planned code (not a fade), play without hover/click, and show its final state with `?static=1`. Fix any that don't match, and report a short table: section · code · ✅ / fixed.
- **Pattern library:** demos on `/patterns` use plain colour placeholders or the current site's images, never an old site's.
- **Prompts (permanent rule):** Claude Code never writes or prints Flow/Veo prompts. The user's director gives them in chat, batch by batch; when the user pastes back the prompts that were run, add them word for word to `site/DESIGN.md` under "Prompts (as run)".
